# 客户地址地图（离线可用）

把订单 / 客户表变成一张**本机可用**的客户分布地图：地址在浏览器本地解析，
数据不出本机、不需要后端、不需要任何地图密钥，**双击 HTML 就能用**。

## 特性

- **六种画法**：标记点 / 点聚合 / 网格聚合 / 六边形聚合（H3）/ 分层着色 / 热力图，随时切换
- **离线底图**：自带省 / 市 / 区县边界，断网也能画；在线瓦片可选，不需要 key
- **多维度**：时间（可拖拽时间轴）、平台、店铺、地区（省 / 市 / 区县钻取）
- **分析页**：12 种图表样式（柱/条/饼/环形/面积/累计/帕累托/表格）、地区钻取、平台×月份矩阵、问答式取数
- **客户画像（粗）**：按人均单量分四档（一次性为主 / 复购型 / 高频复购 / 重度客户）
- **常驻地址 + 辐射圈**：加一个常驻点，看每个客户离它多远、先跑哪一片
- **大文件工具**：上千万行的原始表在本机流式聚合，产出一个几 MB、秒开的汇总表
- **Codex 插件**：`plugins/customer-address-map/`，在 Codex 里一句话就能跑完整流程

## 快速开始

### 1. 直接用（推荐）

双击 **`打开地图.html`**（或 `index.html`），点「导入数据」选一个 CSV：

| 场景 | 导入什么 |
|---|---|
| 想看效果 | `示例_订单数据.csv`（443 行合成数据）|
| 自己的订单表 | 先用下面的大文件工具聚合成**汇总表**再导入（几千~几万行，秒开）|

导入后可以：切画法、拖时间轴、点平台/店铺筛选、点区域钻取、看分析页。
在线底图取不到（断网/内网）时，在「图层」面板把底图切成**本地边界（免密钥）**。

### 2. 从源码跑

```bash
npm install
npm run build     # 产出 app.js / 打开地图.html（仓库里已有构建产物，改源码后再跑）
npm test          # 单测 + 类型检查 + 构建 + 端到端
```

### 3. 处理大文件（几十万 ~ 上千万行）

```bash
node 批量解析大文件.js --input <原始表.csv> --out <输出目录>        # 城市 × 平台 × 月份
node 批量解析大文件.js --input <原始表.csv> --out <目录> --shop    # 再加店铺维度
```

Windows 上也可以直接双击 `一键解析大文件.bat`（自动挑目录里最大的 CSV）。
它会打印一份**数据体检**：行数、解析成功率、去重客户、复购率、平台/城市/店铺 TOP、重复 id、无效手机号占比。

## 支持的数据格式

按**列名**认字段（大小写不敏感，允许包含关系）：

| 用途 | 认这些列名 |
|---|---|
| 地理（任选其一）| `receiving_address` / `收货地址` / `地址`；或 `province`+`city`+`area` 编码；或只有 `province`+`city`（按城市中心点）|
| 时间 | `create_time` / `成交时间` / `下单时间` / `时间` … |
| 平台 / 店铺 | `platform`、`shop_name` |
| 手机号 | `phone`（**只用于去重计数与画像，不会写进结果文件**）|
| 数量 | `客户数` / `数量` / `订单数`（已经是汇总表时当权重用）|

更多细节见 `plugins/customer-address-map/skills/customer-address-map/references/`：
`schema.md`（认哪些列、精度到哪级）、`metrics.md`（客户数/复购率的两种口径）、`troubleshooting.md`（乱码、掩码手机号、没有时间列…）。

## 在 Codex 里当插件用

```bash
codex plugin marketplace add <本仓库的本地路径>
codex plugin add customer-address-map@customer-map
```

然后新开一个会话，说「用 `$customer-address-map` 把这份订单表做成客户分布地图」。
它会按「认表头 → 聚合（打印数据体检）→ 拼分发包 → 自检 → 给结论」的流程走，最后交给你一个双击就能用的文件夹。

## 目录结构

| 路径 | 说明 |
|---|---|
| `打开地图.html` / `index.html` / `app.js` | 可直接双击运行的前端产物 |
| `styles.css` / `ui.css` | 样式（含设计令牌、暗色模式）|
| `src/` | 模块化源码：`main.js`（接线）、`analysis/`（语义层·模型·视图·视觉对象声明）、`map/`（deck.gl 引擎 + 地图逻辑）、`data/`（导入解析·DuckDB 引擎）、`filters.js` / `data-table.js` / `import-flow.js` / `config.js` |
| `tests/` | Vitest 单测 + Playwright 端到端 |
| `scripts/` | 构建收尾、接线自检、备份 |
| `plugins/customer-address-map/` | Codex 插件（skill + 离线小程序 + 截图）|
| `geo-data.js` / `geo-boundary-*.js` | 本地地名库与行政边界（离线可用）|
| `vendor/deckgl` / `vendor/xlsx` | 本地打包的地图引擎与 Excel 解析 |

## 技术选型（为什么这么做）

- **构建成 IIFE 而不是 ESM**：`file://` 下浏览器会以跨域拦截 module，双击即用是这个产品的前提。
- **零框架 SPA**：这个体量的工具，框架的体积与抽象成本大于收益；只有少数交互岛用 React + Tailwind。
- **deck.gl 官方图层 + 原生 Canvas**：散点/网格/六边形/热力/GeoJSON/文字/连线全部用官方图层，不重复造轮子。
- **本地地名库 + 本地边界**：不依赖任何在线地理服务，断网可用、无密钥、无额度。
- **DuckDB-WASM（可选）**：HTTP 模式下做 SQL 聚合与 Parquet 缓存；`file://` 下自动退回 JS 通道。

## 隐私与数据

- 仓库里**只有合成数据**：`示例_订单数据.csv` 是造的假订单；端到端测试用的汇总表也是按需现造的（见下）。
- 真实导出、聚合汇总、客户调研表都在 `.gitignore` 里，不会入库。
- 程序不含上传、埋点、CDN 依赖：解析与统计全在本机，拷到内网机器也能用。

## 已知限制

- 端到端测试开箱即跑：本机有 `汇总_按区县_三维.csv` 就用它，没有就按需生成一份脱敏的汇总数据（`tests/e2e/fixture-data.mjs`，生成物落在 `tests/.cache/`，不入库）。
- `vendor/duckdb/`（约 34 MB wasm）未入库：不用它程序会自动走 JS 通道；要用 SQL 加速就把它放回 `vendor/duckdb/`。
