# 认哪些列

脚本按**列名**认字段（大小写不敏感、允许包含关系）。有哪个用哪个，没有就少一个维度。

| 用途 | 认这些列名 | 说明 |
|---|---|---|
| 地理（三选一，按精度从高到低） | `receiving_address` `收货地址` `收件地址` `地址` `详细地址` | 地址文本 → 本地地名库最长匹配，能到乡镇街道级 |
| | `province` + `city` + `area`（`district`/`区`/`区县`/`县`） | 国标行政区划编码，定位到区县 |
| | `province` + `city`（**没有 area**） | 按**城市中心点**定位到市级；订单表最常见的形态 |
| 时间 | `create_time` `trade_time` `payment_time` `创建时间` `成交时间` `下单时间` `付款时间` `时间` | 拆到"年-月"；没有时间列就没有时间维度 |
| 平台 | `platform` `平台` | 变成可筛选的维度 |
| 店铺 | `shop_name` `original_shop_name` `店铺名` `店铺` | 加 `--shop` 才写进结果 |
| 手机号 | `phone` `手机号` `手机` `电话` `buyer_phone` | **只用来算去重客户数和画像**，绝不原样输出 |
| 数量 | `客户数` `数量` `订单数` `条数` `count` | 已经是汇总表时用它当权重 |

## 精度会体现在哪

- 有区县编码 / 地址文本 → 地图上一个点是一个区县或一个地点
- 只有省 + 市 → 一个点是一个城市（数据里 `353 个城市` 这种）
- 只有省 → 只能到省级

程序会**按数据实际精度**说话（KPI 上写"覆盖城市"还是"覆盖区县"），不用手工解释。

## 和 ddl.txt 的对应

如果你的数据是**两张表分开导出的**（一张有订单号 + 时间/平台/店铺，另一张有订单号 + 收货地址），
先用 `合并订单数据.js` 按订单号合并成一张宽表，再交给本 skill。
