# 常见问题与处置

| 现象 | 原因 | 处置 |
|---|---|---|
| 一行都没解析出来，聚合行数 0 | 列名没被认出来 | 看 `references/schema.md` 对照；把表头改成规范名（`province`/`city`/`platform`…） |
| 中文全是乱码 | 文件是 GB18030（Excel 另存为 CSV 常见） | 脚本会自动识别 UTF-8 / GB18030；还是乱码就先用 Excel 另存成 "CSV UTF-8" |
| 报告里"手机号算不出客户"占比很高 | 平台脱敏成 `***` / 座机 / 串进了地址 | 正常现象：这些行只进订单数。要客户级指标就得让上游给可统计的匿名 ID |
| 数据只到市级，地图看着不够细 | 源表只有 `province` + `city` | 要么接受市级（推荐，快），要么让上游加 `area` 或收货地址 |
| 没有时间维度 | 源表没有时间列 | 导出时带上 `create_time`；否则时间轴、环比同比、月度矩阵都用不了 |
| 输出文件已存在被改名成 .bak | 脚本覆盖前会先备份 | 正常保护；确认无误后删掉 .bak |
| 地图上点很少 / 只有几个点 | 源表地址几乎唯一、或精度只到省 | 用"分层着色"看行政区分布，或用点聚合 |
| 断网时底图空白 | 在线瓦片取不到 | 图层面板把底图切成「本地边界（免密钥）」；或跑 `scripts/serve.js` 起本地服务 |
| 导入几百 MB 原始表很慢 / 卡 | 浏览器不能直接吃大表 | 先 `scripts/aggregate.js` 聚合；规则：>50 MB 一定先聚合 |
| 内存吃紧（上千万行） | 客户级统计要一张全局表 | 用 `node --max-old-space-size=4096 aggregate.js …` 跑；或先按时间/平台切分再分别聚合 |
